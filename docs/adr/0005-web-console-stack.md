# 0005: Web console stack and visual system

Status: accepted.

## Context

The product needs one Web GUI that shares the public API's commands,
permissions and audit semantics. It needs light and dark modes, desktop and
mobile layouts, and explicit loading, error and empty states. The visual
direction is minimal and monochrome, with rich iconography. The console must
work for self-hosted and offline installations under a restrictive Content
Security Policy, and it must not drift from the HTTP contract.

## Decision

- Scaffold with the official `create-vue` generator: Vue 3.5, Vite 8,
  TypeScript 6, Vue Router, Vitest, Playwright, ESLint with
  `eslint-plugin-vue` and Oxlint, and Prettier. TypeScript 6 is the last
  release with the compiler API that `vue-tsc` builds on. Biome was not
  chosen because its documentation still marks Vue support as experimental.
- Build the UI from shadcn-vue components on Reka UI, generated by the
  shadcn-vue CLI with the `neutral` base color, Tailwind CSS v4 and Lucide
  icons (`@lucide/vue`, which replaces the deprecated `lucide-vue-next`).
- Make every theme token achromatic, including `destructive` and the chart
  palette. Because hue carries no meaning, status is always an icon plus text
  (WCAG 2.2 SC 1.4.1). Text tokens meet 4.5:1 (SC 1.4.3). Input borders and
  focus rings meet 3:1 (SC 1.4.11), so they are darker than the shadcn-vue
  defaults.
- Self-host Geist and Geist Mono through Fontsource instead of the CLI's
  Google Fonts import. The saved color scheme is applied before first paint
  by a same-origin script, so no inline script is needed.
- Generate the typed client and TanStack Vue Query options with
  `@hey-api/openapi-ts` from the reviewed OpenAPI fixture. The generated code
  is not committed. Mutations send the command metadata the contract
  requires, including a per-command idempotency key that a retry reuses.
- Each feature module owns its routes and icon-bearing navigation entries.
  The shell renders the registered features and knows none of them, and no
  feature imports another: a lint rule refuses it, and what features share
  lives in shared modules.
- Playwright runs against the production build with the API mocked, in
  desktop Chromium, mobile Chromium and mobile WebKit, and fails on
  horizontal overflow.

## Consequences

- Adding a component is a CLI command, and adding a capability is a new
  feature folder plus one registry entry.
- API changes reach the console as type errors after `pnpm codegen`.
- Dependabot covers the npm ecosystem, and CI type-checks, lints, tests and
  builds the console on every change to it or to the OpenAPI fixture.
